# ユーザー確認の提示形式

情報収集、生成開始前、途中の仕様判断、独立レビューの依頼・省略判断、最終承認など、ユーザーへ回答・選択を求める際に適用する。生成ドキュメントの形式にかかわらず、確認メッセージは以下のMarkdown形式とし、3つの大見出しと順序を固定する。

- 今回の確認メッセージだけで判断できるよう、作業の概要と必要な背景を再掲する。「上記の方針」「先ほどの案」や資料へのリンクだけで説明を済ませず、対象・変更内容・条件と、専門用語の意味を具体的に示す。
- 確認した事実・合意済みの事項と、提案・未確認事項を区別する。説明を埋めるために根拠のない理由や条件を作らない。共通の背景は冒頭にまとめ、各質問の判断材料はその質問の直下に置く。
- 独立して回答できる判断は項目を分ける。例えば、対象範囲の縮小と実行日時・保存期間を一括承認にしない。説明量は判断の難しさに合わせ、短くする場合も確認理由・回答の用途・影響を残す。
- 質問ツールを使う場合も、呼び出す直前にこの形式の本文を提示し、質問番号と選択肢を対応させる。ツールの短い選択肢や補足欄で本文を代替しない。

以下の質問部分は、選択式・情報入力式から必要な型を選び、質問数に合わせて増減する。単純な承認確認では「選択肢と影響」「推奨案と理由」を「採用する内容と影響」に置き換え、承認または変更希望を尋ねる。比較のためだけに代替案を作らない。

```markdown
## ここまでの整理

- **目的**: 今回の作業で何を実現しようとしているか。
- **実施内容と分かったこと**: 調査・作成した内容と、今回の判断に関係する結果。
- **確定済みの事項**: ユーザーが合意した条件・方針。
- **今回確認する理由**: 何が未決で、次の作業にどう関係するか。

## ユーザーへの確認事項

### 1. {決めたいことが具体的に分かるタイトル}

**背景・確認理由**
現在の状況と、なぜ今この判断が必要なのか、回答を何に使うか。
対象となる方針・機能・条件を具体的に説明する。

**選択肢と影響**

| 選択肢 | 採用する内容 | 利点 | 負担・制約 |
| --- | --- | --- | --- |
| A | ... | ... | ... |
| B | ... | ... | ... |

**推奨案と理由**
推奨する案と、今回の目的・制約に照らして適する理由。
推奨を決める材料が足りない場合は、その不足情報を示す。

**回答してほしいこと**
A / Bの選択、または希望する変更内容。

### 2. {入力してほしい情報が分かるタイトル}

**背景・確認理由**
なぜ今この情報が必要なのか、回答を何に使うか。

**必要な情報と判断材料**
回答に必要な条件や、指定によって変わる動作・影響。

**回答してほしいこと**
必要な情報の形式と回答例。
未定でも進められる場合は、その扱いと確定が必要になる時点。

## 回答方法と次の作業

- **回答例**: 「1はA、2は○○」のように番号ごとに回答。
  一部だけ変更したい場合は、その内容を記載。
- **回答後の作業**: 回答をどこへ反映し、次に何を行うか。
```

提示前に、このメッセージだけで「何を・なぜ決めるか」「各案や入力の影響」「どう回答するか」「回答後に何が進むか」が分かるか確認する。確認が必要な条件や承認済みの範囲は各Phaseに従い、この形式のために確認回数を増やしたり、回答済みの項目を再質問したりしない。
