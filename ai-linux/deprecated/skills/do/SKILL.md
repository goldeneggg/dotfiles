# Do

## 入力と方針

タスク内容を受け取り、日本語で進める。
目的、成功条件、対象、制約を会話と既存情報から整理する。
手順の重さはタスク規模に合わせる。

## 手順

1. 必要な事実を調べ、成功条件と未確定事項を把握する。
2. 多段作業では依存関係、実装範囲、検証方法を短く計画する。
3. 既に依頼された対象内の作業を実施する。編集前に対象を読み、ユーザー変更と既存規約を保持する。
4. 成功条件を実際の成果物と適切な検証で確認する。
5. 対象内の失敗を原因に基づいて修正し、必要な検証を再実行する。
6. 結果、検証、未完了事項を報告する。

## 確認が必要な場合

仕様や対象が大きく変わる場合、未承認の破壊的・不可逆操作、権限拡張、重要なコスト判断が必要な場合だけ確認する。
合理的で可逆な作業上の選択は理由を示して進める。
確認前に既に許可された準備を済ませ、具体的な差分・操作・影響を示す。
一部が保留でも、独立して進められる作業を続ける。
Plan mode等の上位の実行制約は守る。

## 委譲

独立した調査・実装・検証で、時間や文脈の節約に効果がある場合にサブエージェントを使う。
少量の作業や共有文脈への依存が強い作業は直接行う。
利用可能なツールと継承方式を確認し、存在しない機能を前提にしない。

委譲指示には目的、対象、制約、編集所有範囲、完了条件、根拠付きの戻り値を含める。
同じファイルを並行編集させず、必要なら隔離と統合を計画する。
メインが結果を統合し、最終判断を担う。

## エラー回復

ツール呼出しの失敗と、正常に実行されたテストの失敗を区別する。
原因を変えずに同じ操作を繰り返さない。
同じ権限・対象内での再読込、入力修正、出力分割等は自律的に行う。
回数だけを理由に安全な回復を承認待ちにしない。
権限制約を別手段で迂回しない。

回復できない場合は、試したこと、原因、残作業、必要な情報や判断を示す。
失敗や未検証を隠して完了としない。
