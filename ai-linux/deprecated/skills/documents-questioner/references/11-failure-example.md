## 11. よくある失敗と修正例

### 11.1 根拠と提案が混ざる

**避けたい質問**

```text
最適なアラート閾値を教えてください。
```

**改善版**

```text
ソースで推奨されている監視指標を抽出してください。
閾値が明示されている場合は、値、単位、適用条件、根拠を示してください。
明示されていない場合は「ソースには記載なし」としてください。

その後、私たちのContextに応じた閾値の決め方を「AIによる提案」として別枠で示し、必要なベースラインデータと検証方法を説明してください。
```

### 11.2 Contextなしで最適解を求める

**避けたい質問**

```text
我々に最適なアーキテクチャを提案してください。
```

**改善版**

```text
まず、アーキテクチャ選定の結論を左右する条件を整理し、現在不足している情報を質問してください。
次に、与えたContextとソースを基に選択肢、トレードオフ、推奨案、見直し条件を示してください。
```

### 11.3 ソースにない具体例を暗黙に作らせる

**避けたい質問**

```text
具体的なコード例と設定例を引用しながら説明してください。
```

**改善版**

```text
ソース内にコード例・設定例がある場合は、それを根拠として説明してください。
存在しない場合はその旨を示してください。
補助例を作成する場合は「AIによる例」と明記し、本番利用前に確認すべき点を添えてください。
```

### 11.4 成功事例だけから一般化する

**改善用の追加質問**

```text
これらの成功事例に共通する選択バイアス、報告されていない失敗、再現に必要な前提条件を分析してください。
同じ手法が失敗した事例、制約、反証を調べるための検索語も提案してください。
```

### 11.5 精密な点数を根拠なく付ける

**改善用の指示**

```text
比較スコアを付ける場合は、評価尺度と根拠を示してください。
根拠が定性的な場合は、見かけ上精密な数値ではなく「高・中・低」などの粗い尺度を使ってください。
情報不足の評価軸は採点せず、判断保留としてください。
```
