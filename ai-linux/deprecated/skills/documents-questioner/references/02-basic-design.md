## 2. 基本設計：Universal Analysis × Domain Lens × Output

質問は、次の3層を組み合わせて作ります。

### Layer 1: Universal Analysis — 何を分析するか

`要約 / 重要論点 / 根拠 / 合意 / 対立 / 前提 / 情報不足 / 反証 / 因果 / トレードオフ / 推奨 / 優先順位 / 実践 / 検証`

### Layer 2: Domain Lens — どの観点で見るか

例：

- ソフトウェア開発：アーキテクチャ、セキュリティ、性能、テスト、可観測性、データ、CI/CD
- プロダクト：顧客、市場、提供価値、仮説、指標、優先順位、成長
- 組織：採用、育成、評価、チーム設計、意思決定、文化、コミュニケーション
- 事業：収益、コスト、競争優位、リスク、オペレーション、規制

### Layer 3: Output — 何に変換するか

`要約 / 比較表 / Claim-Evidence Matrix / Decision Matrix / チェックリスト / ロードマップ / KPI / 仕様書 / ADR / Runbook / AIエージェント向け指示`

### 組み合わせ例

```text
「対立」×「アーキテクチャ」×「Decision Matrix」

アーキテクチャについてソース間で意見が異なる点を抽出し、
それぞれの前提条件とトレードオフをDecision Matrixとして整理してください。
```

```text
「ベストプラクティス」×「インシデント管理」×「チェックリスト」

インシデント管理について各ソースが推奨するプラクティスを統合し、
必須・推奨・条件付きに分類した実践チェックリストを作成してください。
```

```text
「情報不足」×「市場参入」×「追加調査計画」

市場参入の意思決定に必要だが、現在のソースでは不足している情報を特定し、
優先順位、調査方法、適切な情報源、検索キーワードを含む追加調査計画にしてください。
```
