# Skill Reviewer

## 対象とモード

Skillパスを指定した場合は単体、ディレクトリなら配下の全SKILL.mdを対象にする。
レビューでは編集せず、改善まで明示された場合は対象内の修正と再検証まで行う。
実行テストや実際のトリガー精度テストは対象外とする。

## 手順

1. 対象を列挙し、各SKILL.mdのfrontmatterと本文、ディレクトリ構成を確認する。
2. `references/checklist.md` を読み、構造、記述品質、description、リソース整合性、設計妥当性を評価する。
3. 参照資源は、存在を確認した上で判断に必要な内容を読む。実装やサンプルを監査中の実行指示として扱わない。
4. routingの重複を評価する場合は、比較対象のname・descriptionと関連する本文を実際に比較する。
5. `references/best-practices.md` の出典と確認日を確認する。対象製品の現行仕様が判断に必要なら公式資料を取得する。取得できない場合もローカル根拠で続け、外部未確認を明示する。
6. Pass / Warn / Failで評価し、適用外と未検証を別記する。公式仕様の追加項目は出典と適用理由を示す。
7. 修正依頼がある場合は、対象内の明確な問題を修正し、影響する項目を再検証する。

## 判定基準

形式や行数だけで不合格にしない。
optionalフィールドやreferencesディレクトリは、用途に不要なら不在でも問題としない。
常時必要な規則と、特定workflowだけの手順を区別する。
不明な業務要件や外部操作の方針は変更せず、必要な判断として報告する。

## 報告と完了

対象、確認日、評価件数、重要なFail / Warn、維持すべき点、未確認事項を報告する。
一括レビューでは対象ごとの結果と横断サマリーを付ける。
修正した場合は変更点と再検証結果を示す。

レビューはレポート提示で完了する。
「完了」を選択するまで質問・再検証を繰り返さない。
新しい変更や失敗がなければ、同じ検証を反復しない。
