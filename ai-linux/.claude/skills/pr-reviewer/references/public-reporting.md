# レポート公開指針

レビュー結果は、PR コメント、Issue、Slack、メールなどに転記されうる対外公開ドキュメントとして扱う。レビュー対象リポジトリの第三者が、参照先と文脈を当該リポジトリ内で確認できる状態にする。

## 参照可能な情報

- レビュー対象 diff に含まれるファイルパス
- 影響範囲調査で参照した、対象リポジトリ内の git 管理ファイル
- 公開 URL（公式ドキュメント、RFC、CVE など）

## 記載しない情報

- gitignore 対象のローカルファイル（`.env`, `tmp/`, `logs/`, ローカルキャッシュなど）
- レビュー対象リポジトリ外のローカルパスや、マシン固有の絶対パス
- 対象リポジトリで管理外、またはレビュー対象外にあるタスク管理ドキュメント
- サブエージェントが返した内部サマリの引用元パス
- レビューに使用したスキル名・サブエージェント名

外部から見えない資料は推論材料として参照してよい。ただしレポートでは、要件や仕様の本文を直接記載し、外部資料への番号参照や第三者が確認できない出典を残さない。

## GitHubの自動リンクを避ける記法

以下の表記は、無関係な Issue、PR、ユーザー、チームへのリンクや通知を発生させるため、レポート本文では使用しない。

| 避ける表記 | 代替表現 |
|---|---|
| `#数字`、`GH-数字` | 「受け入れ条件 3」「項目 3」 |
| `org/repo#数字` | 「外部要件 3」など、内容が分かる表現 |
| `@username` | 「担当者」「実装者」 |
| `@org/team` | 通常文のチーム名 |
| フルコミットSHA | `path/to/file.ext:42` 形式の該当箇所 |

## 報告前チェック

最終レポートの表示、保存、投稿の直前に、本文全体を点検する。

- [ ] すべてのパスが対象リポジトリ内の git 管理ファイルを指しているか
- [ ] `todos/`, `logs/`, `tmp/`, `.env`, `~/`, `/Users/`, `/home/` など、対象外またはローカル固有の参照がないか
- [ ] 内部サマリの引用元パスや、外部不可視資料への間接参照がないか
- [ ] `#数字`, `GH-数字`, `org/repo#数字`, `@username`, `@org/team` がないか
- [ ] スキル名やサブエージェント名がないか
- [ ] 各指摘が `finding-writing.md` の必須項目と文章指針を満たしているか

問題がある記載は削除または抽象化してから報告する。
