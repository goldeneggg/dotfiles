# Gitignore Optimizer

## モード

レビュー・追加候補の相談は提案のみとする。
作成・更新・最適化の依頼は、必要な編集と検証まで行う。

## 手順

1. 指定プロジェクトまたは現在のリポジトリのマニフェスト、ビルド定義、CI、既存.gitignoreを確認する。モノレポでは下位の.gitignoreも考慮する。
2. 検出した技術に関係するテンプレートをgithub/gitignoreの公式リポジトリから取得する。OS・エディタの全テンプレートを機械的に追加しない。
3. 不足、無関係な候補、プロジェクト固有パターン、秘密情報の除外を比較する。取得失敗は未確認として報告する。
4. パターンごとに対象と必要性を示す。技術スタックが確認できている場合は、形式的な承認を待たない。
5. 編集モードでは既存セクションとカスタムエントリを保持し、関連する不足だけ追加する。
6. 代表的な対象パスと追跡すべきパスで除外結果を確認し、意図しない除外がないか検証する。
7. 変更または提案、理由、検証結果、未確認事項を報告する。

## 保持する制約

- カスタムエントリを、技術が検出されなかったという理由だけで削除しない。
- テンプレートを丸ごと追加しない。
- 既存のコメント構造を尊重し、新しい区分が必要なら技術名のコメントを付ける。
- ファイル末尾の改行を保つ。
- .gitignoreの更新だけで追跡済みファイルが追跡解除されると扱わない。
- index変更、履歴修正、秘密情報の削除・ローテーションは別の操作として扱う。
- 根拠が足りないパターンや意図が不明な削除は変更せず、要判断として残す。
