# Worktree Manager

## 一覧を表示する

呼び出し元のディレクトリで `git worktree list --porcelain -z` を実行する。失敗したら Git のエラーを伝えて終了する。NUL 区切りの各レコードから絶対パス、ローカルブランチ（`branch` の `refs/heads/` 以降）、状態を取得する。

全件を「番号 / パス / ブランチ / 状態」の表で表示する。先頭はメイン worktree。現在地は作業ツリー内なら `git rev-parse --show-toplevel` で特定する。メイン、現在地、bare、locked、prunable の行は理由を示して選択対象から外す。detached HEAD はブランチ欄に短いコミット ID を添える。選べる行がなければここで終了する。

## worktree ごとに選んでもらう

「すべて選ぶと、選択した削除を実行します。途中で『すべて中止』を選ぶと、ここまでの選択も取り消せます」と最初に伝える。

一覧の順に、対象ごとに単一選択の質問を一つずつ出す。Claude Code では `AskUserQuestion` を使う。質問には対象のパスとブランチを示し、次の選択肢を提示する。

| 選択肢 | 動作 |
| --- | --- |
| 保持 | この worktree をそのまま残す |
| worktree のみ削除 | 作業ディレクトリを削除する。ブランチがあれば残す |
| ブランチも削除 | 作業ディレクトリと表示中のローカルブランチを削除する |
| すべて中止 | 今回の操作を取り消して終了する |

detached HEAD では「ブランチも削除」を省く。回答は表示したパス・ブランチに対応づけて記録する。回答待ちの間は削除せず、すべての対象に回答がそろったら追加確認を挟まず実行する。

## 選択を実行する

1. すべて「保持」なら、その旨を伝えて終了する。削除の選択があれば一覧を再取得し、対象を番号ではなく元の絶対パスで照合する。ブランチ、HEAD、選択可否が変わった対象はスキップして理由を伝える。
2. 選択された対象ごとに、呼び出し元から `git worktree remove -- <絶対パス>` を実行する。パスとブランチ名はそれぞれシェルで展開されないように一つの引数として渡す。
3. 「ブランチも削除」を選び、worktree の削除が成功した場合だけ `git branch -d -- <ローカルブランチ名>` を実行する。未コミットの変更や未マージのコミットなどを理由に Git が拒否した場合は、強制削除せずほかの選択を続ける。
4. 結果を対象ごとに簡潔に報告する。片方だけ成功した場合は「worktree は削除済み、ブランチは保持」のように、残ったものと Git のエラー理由を明記する。
