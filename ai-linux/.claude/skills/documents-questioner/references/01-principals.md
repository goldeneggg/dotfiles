## 1. 守るべき5原則

### 1.1 Source / Analysis / Recommendationを分離する

AIの回答では、次の3種類を混同させないことが最も重要です。

| 区分 | 意味 | 回答時の表示例 |
|---|---|---|
| Source | ソースに明示されている事実・主張・数値 | `ソースの記述` |
| Analysis | 複数の記述を統合・比較して導いた解釈 | `AIによる分析` |
| Recommendation | 与えられた目的や条件に応じた提案 | `AIによる提案` |

すべての質問に、必要に応じて次の指示を追加してください。

```text
回答では、以下を明確に分けてください。

1. ソースに明示されている内容
2. ソースを統合して導いた「AIによる分析」
3. ソース外の知識を含む「AIによる提案」

各主張には根拠となるソースを示してください。
ソースだけでは判断できない場合は、推測で補わず「判断に必要な情報が不足」と明記してください。
```

### 1.2 「我々に最適」を尋ねる前にContextを与える

対象の状況を示さずに最適解を求めると、AIが組織・利用者・制約を暗黙に仮定します。必要な範囲で、次のContextを質問の先頭に追加してください。

```text
Context:
- 目的:
- 対象者・顧客:
- 現状:
- 解決したい課題:
- 規模・利用量:
- 期間:
- 予算:
- 人員・スキル:
- 技術・運用環境:
- 必須条件:
- 許容できないリスク:
- 既に決まっていること:
- 今回の対象外:
```

すべてを埋める必要はありません。結論を左右する条件を優先します。

### 1.3 「記載なし」を有効な回答として認める

コード例、設定値、KPI、閾値、成功事例などがソースにない場合、AIがそれらしい内容を補うことがあります。次の一文を添えると、根拠のない補完を抑えられます。

```text
該当する情報がソースにない場合は「ソースには記載なし」としてください。
追加の例や数値を作成する場合は「AIによる例」と明記し、置いた仮定を示してください。
```

### 1.4 引用よりも根拠の対応付けを優先する

通常は長い逐語引用より、各主張がどのソースに基づくか分かることが重要です。表現自体の確認、契約・規約、定義、重要な数値など、原文が必要な場面だけ引用を求めます。

```text
各主張に根拠ソースを対応付けてください。
原文の表現自体が重要な箇所だけ、必要最小限の引用を添えてください。
```

### 1.5 一発で最終回答を求めず、段階的に深掘りする

基本フローは次のとおりです。

```text
理解 → 根拠確認 → 比較・批判 → 判断 → 実践 → 検証
```

最初からロードマップや最適解を求めず、まず論点・根拠・情報不足を明らかにすると、結論の追跡可能性が高まります。
