## 5. Domain Lens：職種・テーマ別の分析観点

Domain Lensは「答えを決める質問」ではなく、「何を見落とさずに分析するか」を指定する観点一覧です。扱われていない観点については「記載なし」と回答させます。

### 5.1 汎用・職種横断

```text
このソース群を、以下の観点で分析してください。

目的、対象者、課題、主要な主張、方法、必要条件、期待効果、コスト、リスク、代替案、実行手順、効果測定、長期的影響

各観点について「ソースの記述・適用条件・反証や留保・根拠ソース」を整理してください。
ソースで扱われていない観点は「記載なし」としてください。
```

### 5.2 ソフトウェア・アプリケーション開発

```text
このソース群から、ソフトウェア開発に関する知見を以下の観点で分析してください。

要件、アーキテクチャ、コード設計、API、データ設計、セキュリティ、プライバシー、パフォーマンス、信頼性、エラーハンドリング、テスト、可観測性、依存関係、CI/CD、保守性、開発者体験

各観点について「推奨事項・アンチパターン・適用条件・トレードオフ・検証方法・根拠ソース」を整理してください。
コード例がソースにある場合は参照し、ない場合に追加例を作るなら「AIによる例」と明記してください。
```

### 5.3 クラウド・インフラ・運用

```text
このソース群から、クラウド、インフラ、運用に関する知見を以下の観点で分析してください。

アーキテクチャ、可用性、スケーラビリティ、性能、ネットワーク、IAM、秘密情報、構成管理、IaC、監視・アラート、ログ、バックアップ、復旧、RTO/RPO、インシデント対応、変更管理、パッチ、キャパシティ、コスト、ベンダーロックイン

各観点について「推奨事項・失敗条件・適用条件・トレードオフ・検証方法・根拠ソース」を整理してください。
具体的な設定値や閾値がソースにない場合は「記載なし」としてください。
```

### 5.4 セキュリティ・リスク・コンプライアンス

```text
このソース群を、セキュリティとリスク管理の観点から分析してください。

保護対象、脅威、攻撃経路、脆弱性、発生可能性、影響、予防、検知、対応、復旧、責任分界、最小権限、データ保護、監査証跡、法規制、サードパーティ、残余リスク

各項目について「ソースに明示された事実・想定されるリスク・既存の対策・不足する対策・検証方法・根拠」を整理してください。
ソースから確認できない脅威は「AIによる脅威仮説」とし、事実と分離してください。
```

### 5.5 プロダクト戦略・ディスカバリー

```text
このソース群から、プロダクトに関する知見を以下の観点で分析してください。

顧客、課題、利用場面、代替手段、市場、競合、提供価値、ポジショニング、仮説、リサーチ、要求、MVP、優先順位、ロードマップ、ステークホルダー、Go-to-Market、ライフサイクル

各観点について「確認できる事実・仮説・反証材料・適用条件・意思決定への示唆・根拠ソース」を整理してください。
顧客ニーズや市場性がソースだけでは確認できない場合は、推測で断定せず検証計画を示してください。
```

### 5.6 グロース・データ分析

```text
このソース群を、成長とデータ活用の観点から分析してください。

獲得、活性化、継続、収益、紹介、ファネル、コホート、セグメント、イベント設計、実験、因果関係、統計的妥当性、定性フィードバック、価格、ダッシュボード、データ品質、プライバシー

各観点について「利用可能な根拠・推奨手法・必要なデータ・交絡やバイアス・判断基準・根拠ソース」を整理してください。
相関しか示されていない内容を因果関係として表現しないでください。
```

### 5.7 ピープル・チーム・組織マネジメント

```text
このソース群から、組織と人材マネジメントに関する知見を以下の観点で分析してください。

採用、オンボーディング、役割、目標、評価、1on1、フィードバック、育成、キャリア、権限委譲、心理的安全性、意思決定、対立解消、会議、チーム構造、文化、知識共有、組織変更

各観点について「推奨事項・前提条件・個人差や例外・望ましくない副作用・効果の確認方法・根拠ソース」を整理してください。
一般論をすべての個人や組織に当てはめず、適用条件と倫理的な注意点を示してください。
```

### 5.8 プロジェクト・業務プロセス

```text
このソース群から、プロジェクト運営と業務改善に関する知見を以下の観点で分析してください。

目的、スコープ、成果物、関係者、役割、依存関係、優先順位、スケジュール、予算、品質、リスク、変更管理、コミュニケーション、意思決定、ボトルネック、自動化、標準化、継続的改善

各観点について「現状・推奨・障壁・成功条件・測定指標・根拠ソース」を整理してください。
理想的なプロセスだけでなく、導入・定着に必要な移行手順も示してください。
```

### 5.9 事業・経営・マーケティング

```text
このソース群を、事業と市場の観点から分析してください。

顧客、市場規模、成長性、競合、差別化、収益モデル、価格、販売経路、獲得コスト、継続価値、主要コスト、能力・資源、パートナー、規制、実行リスク、シナリオ、先行指標

各観点について「確認できる事実・仮定・不確実性・反証・意思決定への示唆・根拠ソース」を整理してください。
市場や競争優位についてソースに十分な根拠がない場合は、その不足を明記してください。
```

### 5.10 学術・技術リサーチ

```text
このソース群を、研究の信頼性と実務への適用可能性の観点から分析してください。

研究課題、仮説、方法、対象、サンプル、比較対象、測定、主要結果、効果量、不確実性、再現性、限界、交絡、外的妥当性、先行研究との一致・不一致、実務への適用条件、未解決問題

各観点について根拠を示し、著者の結論と、データから直接確認できる内容を区別してください。
複数研究の結果を統合する場合、研究条件の違いを無視して単純平均しないでください。
```
